## 关键链路与反例

- 两协议完整 wire、UTF-8 字节/上下文恰好边界、非法 JSON/usage/终结、64 KiB 输出；响应 256 KiB 恰好边界及超一字节、超时、重定向、错误长度和分块/头部异常。
- 准确原请求重放、内容冲突、配置 A→B→A、新旧调用各自冻结目标、整配置拒绝、控制回执查询及分页；配置不清空累计预算。
- 发送前事务回滚、发放提交确认丢失、发放后/远端返回后中断、捕获提交前失败、捕获后重启和结算事务失败；实际双进程争用同一调用只产生一次 POST。
- 取消前发放拒绝、取消后当前结果与历史读取分离、批准撤销和凭据变化拒绝；已发生的原调用计量保持。
- 终结但用量缺失释放执行槽并保留输出预留；非法/高于预留的实际用量保留下界并隔离新发放；可信 `not_sent` 的输入/输出归零但保留尝试次数。
- 应用结算端口失败保留原捕获、整体回滚后可接续；应用控制与 Runtime 在同事务保存，控制重放不重复执行回调，撤权后发放拒绝。
- 内容副本写入丢回执后按原 key 查询，无重复写；读状态不明不擅自写入，错误字节/目标换绑拒绝；内置载荷缺失和批准指针回退拒绝，原件不修造。

上述是有界用例，不能等同完整 RV/MR/CR、全部 SQLite/文件系统故障、设备断电或生产资格。

## 复现与后续

源码：在本项目原虚拟环境运行 `PYTHONPATH=src python -B -m unittest discover -s tests -q`。HTTP 用例需要本机回环权限。安装验证须先构建固定源码 wheel，将 tests/examples 复制到无 src 的独立目录，清除 PYTHONPATH，以原项目解释器 `-I -B` 运行；核对包内实际加载路径与 RECORD，再运行 `examples/serial_consumer.py`。不得让测试的子进程误加载原源码。
