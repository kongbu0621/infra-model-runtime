# 架构与候选公共边界

状态：**Candidate / 待实现和验证**。2026-11-24。以下类型、操作和模块名是设计标识，不是已发布 API。对应[需求](REQUIREMENTS.md)与[实施计划](IMPLEMENTATION_PLAN.md)。

## 模块与唯一所有者

| 模块/端口 | 拥有或承担的责任 | 边界 |
| --- | --- | --- |
| public contracts | 有界不可变请求、绑定、回执、状态和错误 | 无 SDK 对象、业务材料类型或任意可变 dict 共享 |
| configuration / routing | 配置应用修订、目标/策略解析、冻结执行计划 | 不把当前配置重解释为旧请求的新目标 |
| runtime / store | 调用、发放、取消、持久观察、预算与资源占用 | 这些事实只由 Runtime 的公共操作修改 |
| adapters / transport | 协议编码、一次发送、完整捕获及分类 | 网络在锁/事务外；禁止隐式生成重试和重定向 |
| credential / capability ports | 获准秘密的短暂读取、绑定核验、能力证据 | 凭据引用名、提供方报告和实际账户身份不混同 |
| content port | 有界准确字节保存、原意图查询、读回 | 内置有限本地载荷存储用于独立运行；可选外部制品适配，不重建通用制品历史/恢复系统 |
| application integration port | 同一事务内的业务准入、撤权排序和结果关联 | 应用拥有自身规则与记录；Runtime 不解释其业务语义 |

依赖方向为应用 → 公共接口 → Runtime → 协议/存储端口。具体应用实现中立业务端口，不得成为 Runtime 的 import、安装或测试依赖。对外存储只经其公共合同调用；Runtime 的协调记录不是外部制品服务的第二份内容权威。

## 候选调用合同

首期使用版本化的值对象与显式操作，不以厂商 SDK 为公共类型。以下需在首个实现 PR 固定完整字段、错误码和容量；不提供尚不可运行的安装或 CLI 命令。

| 对象/操作族 | 最小语义 |
| --- | --- |
| Request / register | 调用方命名空间、原请求 ID、有界任务类别/输入、输出合同版本、必需能力、处理约束、输出上限、截止时间、可选业务准入引用；完整规范输入指纹与稳定登记回执 |
| Plan / child call | 冻结策略修订、确定的有序子调用集合；每个子项独立 ID、目标快照、attempt、预算池/资源组和状态；父子关系不继承权限或释放占用 |
| Config / check, apply, select, resume | 严格配置检查、期望应用修订和文件摘要、幂等管理 ID、原 pending 接续；检查不授予运行许可 |
| advance / status / list | 推进原调用或返回有界当前观察；列表分页；状态读取不调用供应商 |
| cancel / reconcile | 独立原控制 ID；本地取消和原保存/结算对账；不执行第二次生成 |
| read result | 准确原结果与证据；历史事实和当前可交付资格分列；业务采用仍由应用判断 |
| Error | 错误类别、原合法身份、本地提交确定性、远端执行观察；未知不能折叠为未提交 |

先按原命名空间和请求 ID 查完整记录，再判断是否为相同公共输入。应用内部重新组织的提示变化不得覆盖先成功登记者的冻结输入。配置快照、请求 bytes、错误、状态布局都独立版本化；不支持版本明确拒绝，不默认空账重建。

## 配置解析与原子应用

候选配置分为 `profiles`（协议/服务/模型/凭据引用/能力引用）、`routes`（任务类别与 single/fanout 策略）、`budget_pools`、`resource_groups` 和全局容量。字段名在实现 PR 固定；这里不声称兼容某个既有配置文件。旧格式只经显式版本迁移进入新合同，拒绝静默补默认值改变历史。

每个目标绑定实际协议/映射版本、服务路由、模型、批准凭据修订和能力合同。别名不充当资源或账户身份。新配置先完整验证引用、循环/重复目标、数量/大小/能力和许可边界，再保存原管理意图、原子替换配置、提交应用事件和回执。中断按原 ID 核对；第三种文件内容不得自动覆盖。A→B→A 内容可重复，应用修订不能复用。

新登记在同一配置快照解析整个计划；计划与全部子登记要么一起持久确认，要么都不登记。存储/控制容量此时预留，生成预算与执行槽在各子调用发放时预留。队列满或计划过大在登记前拒绝；可发放子项独立竞争，不提供跨模型“全部已执行”的原子保证。

切换只影响新登记。旧排队任务发放前仍核当前许可、原目标准确绑定、凭据批准、能力、资源和预算；失配阻止或标记过时，不能改成新模型。失败重试、改模型或重新生成是明确的新请求/尝试，保留旧关联和未决占用。

### 配置变化不重建资源和预算身份

资源组与预算池的稳定 ID、约束范围及资源/账户到组/池的归属关系属于持久协调记录，配置中的显示名称不是账本身份。以部署方正确声明的共享资源/账户范围为前提，指向同一受约束资源/账户的新别名须复用原绑定；Runtime 不凭 URL 或名称自动发现真实 GPU、账户或下游代理关系。新登记冻结适用组/池集合，发放时同时核对该绑定仍有效及当前限额，不能给旧请求改绑到空组。

普通配置应用允许显示名、启停与限额变化，但保留原累计、预留、占用和引用。降额低于既有占用时阻止新增发放，不截断旧账或强行释放；停用目标阻止新发放，原查询、取消和对账仍按原身份与当前控制权限处理。配置检查还须核对持久注册表与全部受影响引用，并与发放按同一协调顺序提交；不能只校验新文件内部自洽。

首期普通配置不支持删除或改写已被登记引用的组/池身份、约束范围及资源/账户归属关系，也不支持借合并、拆分或另起 ID 迁走原账。停用后保留定义与历史，ID 不复用；确需重分组须另有显式迁移合同和守恒证据，尚未实现时拒绝整次配置变更、保留原配置和账本。否则“旧调用仍占 G1，新配置把同一资源转到空 G2”就能绕开上限；旧调用已终结但已有消费，也不能通过换预算池得到新的累计额度。

默认模型、任务路由和模型参数仍可按原配置合同更新：新目标满足当前许可、能力和准确资源/账户归属，新登记使用新快照；旧调用保持冻结目标并重核当前准入。这里受保护的是资源/预算归属，不能把它误解为永久锁定所有模型配置字段。

## 同库事务集成

首期选择**单个本地 SQLite 协调事务 + 公开的版本化事务集成端口**，避免把业务撤权检查和模型发放拆成两个数据库中的独立成功。单独使用时 Runtime 自己提供协调库；嵌入应用时由适配层接入同一协调库与协调锁。不能把一个普通返回 true 的回调当作原子许可。

候选 `LocalTransaction` 由协调器创建和结束，限定本次连接、线程、事务及生命周期。应用端口仅访问自己拥有的表；Runtime 仅访问自己的表。端口禁止嵌套提交/回滚、网络/外部存储 I/O、长任务和在事务结束后保存句柄。异常使本次组合写入整体回滚。它是可信同进程扩展合同，不是阻止恶意 SQL 的安全沙箱。

| 边界 | 需在同一短事务确认的事实 |
| --- | --- |
| 登记 | 原请求查重、应用准入版本/依赖检查及应用关联、Runtime 冻结计划/子请求、存储与控制预留、原回执 |
| 发放 | 当前配置/许可/准入版本、取消和截止时间、能力资格、所有预算与共享资源组余量、唯一发放令牌和占用 |
| 撤权/纠错 | 应用修订与其持久准入失效事实；同一协调顺序先于发放时阻止旧依赖发送 |
| 观察/结算 | 原调用观察、准确成本/隔离事实、本人占用释放、结果关联；应用结果准备完成后以当前依赖作最终采用资格判断 |

正文、协议解析及外部内容读回在事务外完成，进入事务重新核对原内容摘要、依赖修订和目标对象绑定。业务输出不合格仍需保存真实成本与终结事实；意外应用端口故障则回滚本次组合提交，保留原捕获供恢复，不能因此重发。后续当前读取仍复核权限，历史资格不覆盖今天的决定。

未证明事务端口能保持这些约束之前，消费者继续原实现；不能用迁移便利放宽语义。跨库部署未来须另有可验证的持久交接协议，交接未确认时禁止发放；本版不实现分布式事务。

## 调用事实、并发与恢复

保存相互独立的事实轴：登记、唯一发放、传输观察、远端终结、捕获完整性、结果保存、输出合同、usage 结算和取消。展示状态是这些事实的投影，不允许单个 SUCCESS 覆盖未完成的轴。

可用结果至少要求完整捕获、远端终结、输出合同合格与准确保存均确认；不足时只能返回状态或获准诊断，不能交付为合格候选。usage 缺失另保留预算预留，不伪造零成本；当前读取还检查取消与许可，业务采用继续由应用确认。

1. 登记和输入保存确认后，worker 在短事务争取一次性发放令牌，同时预留全局/预算池及全部适用资源组额度。任一失败全部回滚，不“先占一个组再等待另一个组”。
2. 只有本次确定提交且持有令牌的执行者能发送一次。提交回执丢失或发放后进程退出，即使怀疑尚未发送，也只能沿原身份核对，不能重建令牌。
3. 网络在事务外。响应捕获先持久保存，再按原内容意图保存/读回；保存未知不重新生成。完整终结证据确认后才可释放对应执行槽。
4. 用量结算独立于执行槽：终结已确认但 usage 不足时可以释放执行资源，费用预留继续保留；本地终结证据尚未持久确认时不可释放。迟到更高用量不得丢弃或截断。
5. 无可靠远端查询能力的模式只恢复本地已捕获事实，真正丢响应仍 UNKNOWN。后续查询/远端取消必须绑定原目标、权限和有限控制额度；查询失败或 NOT_FOUND 不自动等于未执行。

调度首版按持久登记顺序和稳定 ID 打破同序，跳过暂时不满足资源条件的子调用并记录原因；有界分页推进，不无限扫描或忙等。资源组限制采用与调用共享的原子占用，默认并发 1，显式配置与验证后才增加；同服务的多个别名累计到同一组。多进程争最后一个槽、进程重启和迟到释放必须按 attempt 身份核对，不释放后来请求的槽。

截止时间从登记起覆盖排队和网络。重放、重启不续期；进程内用单调计时限制实际网络等待，持久绝对截止用于重启接续，时钟异常不能扩大原授权窗口。发放后超时不证明远端终止。父计划取消展开为各子调用的有界控制，逐项报告，不能因部分取消成功宣称所有远端已停止。

### 父计划取消先阻止全部新发放

父计划取消先核对原命名空间、准确计划身份及当前控制权限，以原控制 ID 在与子调用发放相同的协调事务顺序中持久确认父级取消标记及回执。每个子调用发放、当前交付和应用当前采用均须核对这个标记，不能只查自己的取消行。父标记先提交时，即使该子项尚未轮到分批处理，也不得发放或作为当前可采用结果；子发放先提交时则保留在途事实。父取消不清除已发放/UNKNOWN 的占用和预留，终结与费用仍逐子核对；获准历史读取保持历史含义。取消不撤销已提交的采用决定或已发生的外部副作用，不能删除原成功事实。

逐子控制和状态汇总在上述标记之后有界分页接续，不持锁执行网络或要求一次处理全部子项。父标记与稳定回执必须整体提交：未确认则按原控制 ID 查询，不能把“开始遍历子项”报告为取消已生效；响应丢失、分页中断或重启不撤销已确认标记，也不改写原回执为最新进度。状态另列本地取消是否确认、逐子处理进度及远端未决事实。

此父子集合是 Runtime 中已冻结的 fanout 计划；应用修订 lineage、同材料来源或普通关联 ID 不自动成为取消传播关系。单独取消一个子项不取消兄弟项；需要覆盖多个独立评审/修订请求时，应用须显式保存作用范围及自己的准入失效，不可假设普通关联关系具有父取消语义。

## 预算、容量与持久存储

所有适用预算按精确整数累计，持久/公共传输用有界规范十进制表示，拒绝布尔冒充整数、浮点和损坏总账。发送前预留调用次数、完整 wire bytes、输出上限等已定义单位；usage 映射明确 input/output/total/reasoning，缺失不填零，reasoning 不重复收费。

实际超预留如实记账，隔离受影响目标，并按共享池剩余额度判断后续任务。不能只截断报告、换别名复活能力或把所有无关资源永久停住。合法配置增额保留全部历史；降额不抹掉旧占用。

登记同时预留有限控制/结果存储位置，避免自动任务吃掉自己的取消/对账通道。各维度上限、异常记录和有限管理增额合同须在实现前固定；不提供无限对账、无限日志或自动删除历史来回收预算。真实 I/O 故障仍可能使读取或控制失败，不能把逻辑预留宣称为物理空间保证。

协调存储故障时停止该协调范围的新发放；写入结果不明保留 unknown，不能把内存取消或结算视为已保存。恢复后先按原身份核对持久事实，再允许正常接续；读取失败不是记录不存在。

存储绑定 schema 版本与原协调域身份，检查请求/计划/占用/控制双向引用和总账一致性；部分表缺失或坏历史拒绝，不初始化成全新零状态。原内容由本地有界载荷或外部 content port 保存。外部写入使用持久原意图、幂等身份、准确字节读回，原目标绑定贯穿准备、提交及返回。

## 可选监督的接缝

[可选监督合同候选](OPTIONAL_SUPERVISION.md)定义观察、评审请求/报告与应用关口的衔接。评审模型也经 Runtime 普通生成路径调用，拥有独立身份、目标绑定与预算；评审网络 I/O 始终在事务外。业务标准、试用/限定任务资格及最终继续决定归应用/原控制 owner，不增加 Runtime 业务权威。

应用把关口版本纳入其准入依赖，在发放/采用事务中重核准确被评审对象、必需报告和当前权限。缺失或未知不得视为不需要检查；历史报告不会因为模型判了 pass 自动覆盖新的输入、动作参数或策略修订。新无监督任务无需评审模块；已选择的 gate 不因故障隐式降级。每个监督调用仍遵守原取消、UNKNOWN、容量和资源规则，业务等待不应占住已终结调用的执行槽。

应用端口区分评审取证/发放与业务采用：有效评审计划可在其目标关口待检查时取得准确候选，但仍核完整性、当前读取和评审处理许可；不能让评审依赖自己要解决的关口。默认 off 不抹去旧计划，缺少评审模块不妨碍基础 Runtime 查询、取消和对账，尚不能作出的应用判断保持待检查。抽检/建议不增加采用关口，但仍参与原共享预算与资源竞争。

## 兼容和升级

协议适配、公共合同、存储布局与发行版本分开记录。首个包为 alpha 候选，支持的 Python/OS/文件系统矩阵以实际安装验证为准。迁移保留原请求、回执、输入、配置、未知占用、取消、用量和内容引用；无法无损转换时明确拒绝并保留原件。

升级先停止新发放、核对原调用并冻结全部持久写入，再在副本验证迁移；只有一个活动写入者。尚未产生新写入时可回退已核对副本；产生新发放、结算或控制后不能还原旧账抹去这些事实，须向前修复或保持暂停。实现顺序及各项 NOT_RUN 见[实施计划](IMPLEMENTATION_PLAN.md)。
