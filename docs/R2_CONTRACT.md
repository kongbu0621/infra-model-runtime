# R2 串行模型调用候选合同

`0.1.0a1` alpha；存储 `r2.store.v1`，请求/观察为 `r2.*.v1` candidate。公开接口见包导出与[独立示例](../examples/serial_consumer.py)，准确安装与验证见 [R2 验证记录](R2_VALIDATION.md)。R2 复用 R1 的事务、发放、预算、取消和观察实现，没有建立另一套预算账。`Runtime` 继续读取 R1 合成库，`ModelRuntime` 读取 R2 库；两者拒绝互开，不自动迁移或重建旧库。

## 技术栈与职责

| 层 | 实际技术 | 负责什么 |
| --- | --- | --- |
| 公共值与调用入口 | Python 3.11+、冻结 dataclass、`ModelRuntime` | 命名空间/原请求、统一状态、配置、批准、取消、查询与接续 |
| 配置 | 有界严格 UTF-8 JSON，完整快照及单调修订 | 最多 8 个目标；切换默认目标只影响新登记，旧请求冻结原目标 |
| 协议 | 两个标准库适配器 | Responses 和 Chat Completions 的非流式 JSON 对象模式；不执行工具 |
| 网络 | `http.client`、受时间限制的子进程 | 一次 POST，无 SDK 隐式重试、重定向或环境代理；覆盖 DNS 与慢响应的总时限 |
| 持久核心 | 本机 SQLite、`BEGIN IMMEDIATE`、FULL 同步 | 原子登记、批准、发放、预算、取消、响应捕获、结算及应用端口 |
| 内容 | 有界 SQLite BLOB、SHA-256、可选 `ContentPort` | 精确保存输入/wire/原响应；可选按原内容身份导出和独立读回 |
| 凭据 | 环境变量或 owned 0600 文件、HMAC 对等检查 | 仅持久引用和带私钥的校验标签；变化后需新的批准 |
| 构建 | setuptools/wheel，运行依赖为空 | 可独立构建/安装，不依赖业务应用、Ledger 或第三方模型 SDK |

支持范围为可信单宿主、本地文件系统、串行执行。多个进程可争用同一本机库；这不等于多模型并发、共享 NAS SQLite 或分布式额度。Runtime 文件为本人所有、0600、单硬链接；原库缺失、损坏或布局不匹配时拒绝，必须先核对原记录。

## 操作与约束

| 入口 | 约定 |
| --- | --- |
| `ModelRuntime.create(path, configuration_bytes, application=None)` / `ModelRuntime(path, application=None)` | 排他建新合成库或打开原库；已有目标不覆盖；应用身份与版本匹配 |
| `configuration()` | 返回当前修订和规范 JSON bytes；读取不调用模型 |
| `configure(control_id, expected_revision, bytes)` | 全量校验后同事务发布完整快照与回执。A→B→A 是不同修订；同管理身份不同输入冲突；有调用后预算池/资源组不可换名清账 |
| `approve(control_id, profile_name, account=..., service_revision=..., capability_contract=bytes)` | 宿主明确批准准确目标、账户引用、服务修订、凭据及能力证据；无网络。它是宿主的明确声明，**不是自动能力发现或真实服务验证** |
| `revoke(control_id, profile_name)` | 同一事务顺序撤销目标批准；旧发放、响应和用量保持。批准历史保留并核对当前投影，不能把旧批准回填为当前许可 |
| `submit(Generation(...))` | 原 namespace/request_id 加完整不可变输入判重；冻结配置、批准与完整 wire，登记应用关联并为响应留逻辑容量；不发送 |
| `run(namespace, request_id)` | 在凭据预检后，事务内复核原批准、目标、取消、截止、应用条件及预算，再发放一次。已经发放的请求只尝试本地恢复，不能重得发送令牌 |
| `recover(namespace, request_id)` | 仅结算原已保存响应；没有响应时保留 UNKNOWN，不查询供应商、不重新生成 |
| `cancel(namespace, request_id, control_id)` | 发放前阻止发送；发放后只确认本地取消，不声称远端停止、不释放未知占用 |
| `status` / `list_calls(namespace, after=..., limit=32)` / `budget` | 原状态、最多 64 条分页、准确累计账；状态与原登记回执不同 |
| `read_result(..., history=False)` | 读取可用 JSON 对象文本；取消后当前读取拒绝，历史读取另查应用权限 |
| `read_payload(..., role)` / `copy_payload(..., port)` | 原准确输入、wire、响应的获准历史读取/可选导出；不触发生成 |

`Generation` 包括 namespace、request_id、task、input_text、allowed_profiles、output_limit、deadline_ms 和可选 admission_ref。task 是宿主定义的有界标识，不含知识材料、评价或回答的私有类型。应用只处理统一请求和结果；适配器型号、端点、凭据引用与额度由配置/管理面提供。配置无法把未获准的目标自动变成可发送目标。

能力合同字段为 `chat_output_parameter`（`max_tokens` 或 `max_completion_tokens`）、`context_tokens`、`input_tokens_per_byte` 和 `evidence_ref`。发送前按**完整 wire 字节**乘保守输入 token/byte 界加输出预留检查上下文。证据须由宿主事先验证并明确提供；一个简单成功响应不代表工具、多模态、流式输出或另一模型也被支持。已有应用的探测/接受流程及外发权限由 R3 适配继续接入，不能跳过原规则。

配置 JSON 示例由独立示例完整构造，schema 为 `model-runtime-routing-v1`。它不接受业务材料订阅等应用配置。`configure` 接收不可变 bytes，原子发布的 SQLite 快照为本组件权威；外部 JSON 文件是输入，不是另一个可直接编辑的运行权威。原应用的文件意图、锁和恢复逻辑留在消费适配，不在此重复实现。

## 状态、预算与恢复

原始请求正文最多 64 KiB；完整 wire 还要满足目标的最多 64 KiB 限制，因此可用正文通常更小。单次响应捕获最多 256 KiB，JSON 输出最多 64 KiB。协议拒绝重复 JSON key、非法数字、超深/超多节点、截断、拒绝/工具结果等。提供方终结、输出合格、用量完整和业务采用分别判断。

累计预算单位为发放次数、完整 wire 输入字节和输出 token 单位；不是货币。一个资源组、一个预算池、一个执行槽；已知部分用量按下界累计，其余预留保留。终结且用量完整才解除剩余输出预留；终结但用量未知可释放执行槽，不能退款。非法或超出原输出预留的用量保留实际下界并隔离新发放；本版没有清空隔离入口。可信传输证实 `not_sent` 时，保留发放尝试次数，输入和输出计零。

发送时限为原请求 deadline 与该次配置 timeout（1–120 秒）较早者；等待发放与网络不会重置原绝对截止。实际传输同时受剩余墙钟窗口和单调时钟控制；检测到回拨时不发送。deadline 不是供应商已停止的证明，也不是结果采用期限的统一定义，应用可另设采用期限。

顺序为：

1. 同事务保存原输入、完整 wire、配置/批准引用及应用登记。
2. 凭据预检；事务内重新准入，记录一次发送资格、预算与应用状态。
3. 事务外执行至多一次 HTTP POST。
4. 同事务持久保存有界原响应及传输事实。
5. 从保存的准确字节重新解析，调用应用结算端口，共同提交用量、槽位与应用结果。

步骤 2 后崩溃且没有步骤 4 的记录，继续保留原未知占用，即使实际上还没来得及发送。步骤 4 已完成而步骤 5 失败，原响应保持，可重开后本地接续；不能新建调用冒充恢复。应用端口异常整体回滚该次结算，正常业务不合格应记为不可采用，不阻止真实费用落账。

R2 没有远端查询/取消或新的可信迟到证据导入接口；无最终用量的预留可能长期保留。R1 的有序观察核心保留，但不能通过它打开 R2 库注入任意供应商事实。供应商内部重试、真实模型质量、成本定价、完整磁盘故障/设备断电矩阵仍待独立验证。

## 内容与容量

内置有界捕获用于独立运行，不实现通用制品版本/发布/恢复系统。每次登记为输入+wire+完整 256 KiB 响应保留逻辑空间，累计最多 128 MiB；最多 256 个请求、32 个待发请求。历史不会自动删除；耗尽后拒绝新登记。逻辑容量不是物理磁盘预分配，数据库索引、JSON、日志另占空间，磁盘故障仍按原身份恢复。

普通配置/批准/撤销合计最多 128 个持久控制记录；每调用沿用最多 8 个取消记录。R2 每请求只接收该次 HTTP 捕获产生的一个观察，重放不新增。输出在事务事实中与 SHA 绑定；内部 JSON 解码上限 8 MiB 用于容纳合法转义组合，不能据此绕过正文/响应限额。

可选 `ContentPort` 先保存导出意图，再在事务外按不可变 `ContentKey` 读取；只有确认不存在才 `put_if_absent`，之后逐字节读回确认。写入返回丢失时重用同一个 key 查询；不创建新导出身份或生成请求。目标绑定不许悄悄换成另一个存储。它是可选副本，R2 原调用恢复继续使用本地有界捕获；外部 Ledger 成为消费者内容权威的接入与迁移属于 R3。

## 版本、许可和交付边界

本轮仅发布审阅代码与候选 wheel，不上传 PyPI、不创建 Release、不声明稳定 API。运行依赖为空，构建依赖固定为 setuptools 84.0.0 / wheel 0.48.0；构建工具不打包进运行 wheel。许可证仍未选定：保留仓库现状，不擅自新增 MIT/Apache 等授权，也不把 public 可见性当作开源许可。正式对外发行前必须落实许可证。

R2 的独立包/合成验证不改变已有应用安装；R3 还需原身份、历史、凭据、Ledger 引用、UNKNOWN、预算和业务采用的迁移/适配验收。多模型并发、自动路由、监督及真实服务另按 R4/R5 与各自计划实施。
