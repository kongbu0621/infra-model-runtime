# 可选模型监督与检查关口

2026-11-24，**Candidate / 设计，尚未实现**。这是[需求](REQUIREMENTS.md)与[架构](ARCHITECTURE.md)的可选扩展。监督关闭时，基础 Runtime 可独立安装和运行；既有协议、权限、预算、状态及完整性检查继续生效。

## 必要性与范围

可选监督用于检查开放式任务是否满足目标、是否遗漏约束、过程是否偏离预期，以及关键步骤是否有足够依据继续。它也支持对尚未熟悉的模型进行受监督试用，再按具体任务证据决定使用范围。复杂任务的潜在价值更大，但不将“多一个模型”直接等同更可靠。

超时、额度、格式、编译和可执行断言优先使用程序验证。模型评审检查程序难以完整表达的要求，仍结合原始证据和必要的人工抽查。先以少量代表任务验证检出、误报、漏报、耗时/成本和人工返工，再扩大使用；不默认每次调用都增加一次模型评审。

过程指应用暴露的目标、步骤、工具实际返回、阶段产物与状态事件；不能假设读取模型未公开的内部推理。只有最终响应的接口不具备逐步语义监督能力。Runtime 提供模型调用事实，应用/工作流提供任务过程和实际环境结果；执行者的自述不能替代这些证据。

## 运行观察、语义评审与继续决定

“是否正常”与“是否符合预期”分别判断，关闭模型监督不关闭基础运行观察。

| 层次 | 判断内容与依据 | 是否调用评审模型 |
| --- | --- | --- |
| 运行观察 | 排队/发放/终结、超时、预算、响应完整性、错误及恢复，来自 Runtime 持久事实与程序检查 | 不需要；读取状态本身不发起生成，不新增必需监控服务 |
| 语义评审 | 是否完成目标、遗漏要求、证据是否支持结论、步骤是否偏离；结合固定标准与可核查材料 | 可选；按抽检、建议或关口策略调用 |
| 继续决定 | 是否可以发放指定动作或采用准确结果；核对当前权限、必需检查及有效报告 | 由应用/原控制层作决定，不能直接把模型 pass 当执行令牌 |

过程观察交接至少关联任务/attempt、检查点、原事件 ID、生产者及其状态修订、证据版本/引用；按生产者的持久顺序处理，不能凭不同机器的时间戳推导全局顺序。去重绑定事件、冻结策略、计划内评审位置及明确轮次；同一评审意图的重复投递找回原登记，不重复发放。多个计划内评审者各有身份，显式新轮次/替换另建关联请求，不误判为重复，也不因消息重投自动新增轮次。旧事件或乱序到达不能覆盖较新的关口状态。所需证据缺失、修订断档或来源不明时明确报告覆盖不足，gate 保持待检查。只要求当前检查范围的完整证据，不要求采集所有日志或隐藏推理。

消息/日志中有“成功”不等于权威状态已更新。恢复先从原 owner 查询准确事件和结果；尚无过程入口的应用只支持结果检查，不宣称实时过程监督。是否告警、暂停或通知属于应用的显式策略；状态查询、观察事件和模型建议本身不触发新的副作用。

## 三方职责

| 所有者 | 职责 |
| --- | --- |
| Runtime | 中立调用与可读观察、版本化状态、身份、预算、共享资源和恢复；监督模型调用复用相同运行合同 |
| 可选评审模块 | 按固定标准组织获准证据，调用一个或多个评审者，保存各自问题/依据/覆盖及不足；不直接拥有任务执行权 |
| 应用或已有控制层 | 定义预期、关键步骤、使用策略及模型适用范围；核对评审、程序验证与当前授权后决定采用、暂停或推进 |

先在消费应用提供可插拔模块，不新增强制服务或另一套生产控制器；公共仓描述通用观察/交接合同。是否独立成另一个组件由实际复用和生命周期另评。业务标准、模型使用资格及监督关口记录不进入 Runtime 的全局模型“信用库”。

执行者和评审者均可选择已配置、获准且满足要求的本地或商业目标；可以不同，也可以同一模型的不同调用。同模型复评或多模型一致不自动形成独立证据。更强或更熟悉的模型可以担任评审者，其适用能力仍需在相应任务上核查。

## 可选模式与配置

下列为候选配置语义，字段名/序列化将在实际实现时固定，不是可执行配置示例。

| 配置项 | 候选含义 |
| --- | --- |
| 模式 | `off` 关闭；`sample` 抽检；`advisory` 建议；`gate` 指定检查关口 |
| 范围与触发 | 任务类别、陌生/变更模型、关键步骤、异常事件、确定的抽样规则；不能只凭模型自报置信度触发 |
| 检查点 | 方案形成后、关键动作发放前、阶段产物形成后、最终采用前；事件有准确阶段/版本身份 |
| 评审目标 | 一个或有上限的多个已批准 profile、必需能力、显式路由；不可用不自动换到未获准商业服务 |
| 标准与证据 | 版本化标准、适用条件、必需程序检查、获准原件/工具结果/状态引用及覆盖要求 |
| 多评审决策 | 预先定义必需检查、分歧/证据不足处理；不默认多数票或平均分通过 |
| 资源与失败 | 总及分项预算、输入大小、并发、等待时限、评审/修订轮数、不可用时处理；不豁免全局额度 |

默认 off，不加载评审依赖或发出监督调用，也不要求配置评审模型。sample/advisory 不阻塞原有允许路径，但明确显示未评审、异常或不确定；程序本来要求的检查不能因此关闭。gate 只约束被选定的任务/步骤，不成为全部 Runtime 请求的必经路径。

选择 gate 却没有评审实现、所需目标/能力或可执行策略时，拒绝启用或将相关步骤保持待检查，不能回退成 off。超时、预算不足、坏响应、分歧及证据缺失均不自动通过。预先允许的替代方式可以是另一获准评审者或有权限的人工判断，须另记决定及依据；它不是伪造原评审成功。

## 动态切换与固定身份

新登记的评审捕获当时策略/标准修订、被评审对象版本及评审模型绑定。配置变化作用于后续评审；已登记评审不原地换模型或输入。需要改用其他评审者时，新建关联请求，保留旧评审的取消/UNKNOWN/费用，不重复使用原请求 ID。

应用可按预先定义的条件在关键节点启用监督。对在途任务增加、撤销或改变关口属于应用的显式策略变更，需获准、留痕并与动作发放排序；改全局默认配置不能清除旧任务已绑定的关口。待采用结果按当前有效策略和对象修订重新判断，旧报告不得自动迁成新标准下通过。已发放的动作不能追记为“此前已受监督”，撤销检查也不能撤回远端动作。

模型使用范围由应用或原治理 owner 保存，建议分为未评估、受监督试用、限定任务范围已验证、需重新评估。记录具体模型/服务配置可识别版本、任务/风险范围、证据、限制、决定者和修订；版本不可识别则保留未知，不能据别名猜测相同权重。

范围扩大、版本/提示/工具/环境变化按实际影响重新评估；不因跑分、厂商、国别、一次成功或自报信心自动提升。减少监督需要适用证据和明确策略修订；熟悉模型在关键步骤仍可要求 gate。使用资格与 Runtime 的协议能力、凭据批准、处理授权分别判断，任一不能替代其他条件。

## 检查交接与采用

1. 应用先形成固定检查包：任务/attempt/检查点、目标与标准修订、候选动作或产物的准确版本/摘要、必需证据清单、当前处理许可。覆盖不全明确记录，不静默截断后声称完整检查。
2. 可选模块经 Runtime 登记独立评审请求，在事务外调用和解析。评审对象中的文字是待检查数据，不能改写标准、授予权限或触发工具副作用。
3. 保存结构化报告，至少含评审身份及准确绑定、`pass / issues_found / insufficient_evidence` 判断、问题/证据定位、覆盖和限制。模型调用完成只证明拿到响应；结构合格也不证明评审意见正确。
4. 应用核验必需报告与程序检查，在原动作发放或采用的短事务中再次比较对象摘要、标准/策略修订、读写权限、取消与有效关口；满足配置条件才登记继续决定。模型网络调用不得进入该事务。
5. 对象/输入/动作参数、适用标准或关键依赖变化后，原报告保持历史，但不再据此放行变化内容。关键动作必须在执行前检查；执行后评审只能形成事后观察，不能宣称预防了已经发生的副作用。

关口状态由应用维护，例如 not_required、pending、satisfied、blocked、unknown；与评审 Runtime 调用状态及模型判断分列。只有明确配置/决定才能产生 not_required，缺失记录或读取失败不能解释为不需要检查。决定、所用报告和目标身份持久绑定；提交不明沿原决定查询，不新建动作重试。

监督意见可形成补证或修订建议；是否自动执行修订另由明确策略控制，每次新生成和有副作用动作均走原身份/授权/预算合同。不得默许无限重评、自动自我批准或让评审者覆盖失败的必需测试。

## 成本、信息与恢复边界

- 评审是普通模型生成调用，独立记账并受同一全局/预算池/资源组约束，不伪装成免费的取消/对账控制操作。有限额的修订链也计全部真实成本。
- 业务“等待评审”不是模型正在执行：执行调用已持久确认终结后按原规则释放执行槽，未结清用量仍保留。不能占着唯一执行槽等待排在其后的评审者。UNKNOWN 仍占相应资源；评审无法运行时等待/超时，不强行释放旧槽。
- 限制评审数量、递归深度和修订轮数，拒绝自引用、循环等待及默认“监督者再自动接受监督”；被评审对象冻结到具体事件/产物，不追逐不断变化的活日志。
- 应用登记同一监督/修订链的稳定预算归属和整体截止，绑定各次普通调用；每次评审、替换评审者或修订只使用剩余额度/时间。换模型、拆子请求、重启或新增请求 ID 不重置该链上限；各调用仍分别保留原身份、用量和 UNKNOWN。增加额度或期限必须是获准的显式策略修订，保留原消费；不得覆盖旧调用截止或复活已过期发放资格。到期后停止新评审/修订发放，gate 不通过；已有远端调用仍按原事实对账。
- 允许执行模型读取不等于允许另一个评审模型处理。按评审目标重新核外发/读取范围；最少必要证据也须保留覆盖缺口。原材料不出境/不外发等限制同样约束监督链。
- 评审故障、取消、迟到、保存未知和重启遵守原 Runtime 合同。更换评审者不清账；报告迟到不恢复被取消或过时的任务。

## 分阶段验证

本设计不改变串行核心抽取主线。先保留中立观察与准入端口；首个应用接入后，以结果抽检/建议验证收益，再按具体关键步骤增量实现 gate 和过程检查。gate 尚未实现时明确拒绝使用该模式；不把关键任务临时当 advisory 执行。完整复杂 Agent 监督平台不作为基础包交付前置。

| ID | 待验场景 | 预期 |
| --- | --- | --- |
| SV-01 | 未配置/未安装评审模块，模式 off | 原调用链独立可用，无监督调用与额外评审持久写入；基础检查保持 |
| SV-02 | 单/多评审、本地/商业选择和切换 | 新评审正确绑定；旧身份/目标/报告不变，未批准目标拒绝 |
| SV-03 | sample/advisory 超时、分歧和坏报告 | 原允许路径保持，记录未评审/问题；不伪造通过 |
| SV-04 | gate 缺实现/证据/预算、超时或评审者不可用 | 相关步骤不发放；替代决定另留证，不静默关闭 |
| SV-05 | 通过后改产物/参数/标准、撤权/取消与发放竞争 | 旧报告不能放行新目标；短事务排序，原历史保持 |
| SV-06 | 评审通过但必需测试失败，或声称完成而实际状态未变 | 不采用；独立证据与程序检查不被模型结论覆盖 |
| SV-07 | 响应丢失、持久化未知、迟到报告与重启 | 原身份对账、不盲目重发、不恢复取消/过时资格 |
| SV-08 | 共享唯一资源、UNKNOWN 占槽、循环评审 | 已终结资源正常释放、无互相等待；未知仍占用、循环与超额拒绝 |
| SV-09 | 被评审文本要求改规则、外发不获准、截断证据 | 不改变策略/权限；拒绝或证据不足，不声称完整监督 |
| SV-10 | 模型版本/任务范围变化、减少监督、成熟模型关键步骤 | 资格依准确范围和显式决定变化；关键关口不自动消失 |
| SV-11 | 继续决定提交前后中断，缺失关口记录 | 原决定恢复、无重复动作；unknown 不转成 not_required |
| SV-12 | 有/无监督对照 | 分别记录真实问题检出、误报/漏报、质量、返工、成本/延迟；收益未证实保持未知 |
| SV-13 | 监督 off、运行异常及只读观察 | 原状态/预算/错误可查；无新增评审调用，观察不授予执行权 |
| SV-14 | 过程事件重复、乱序、缺失、显式多评审/新轮次及重启 | 同意图不重复发放；合法多评审有独立身份，旧事件不覆盖新状态；缺证据不通过，恢复核原 owner |
| SV-15 | 换评审者、修订与并行评审争最后额度/期限 | 同链累计原子受限，整体期限不自动续期；旧 UNKNOWN 不清零，过期不再发放 |

上述全部 **NOT_RUN**。样本由独立可核查材料建立，保留开发与评估范围；按任务类型报告，不以单次演示或监督者自评宣称普遍有效。
