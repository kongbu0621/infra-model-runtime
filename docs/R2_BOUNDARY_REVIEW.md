## 确认并修复的问题

| 问题与触发条件 | 旧行为与修复 | 验证 |
| --- | --- | --- |
| 调用目录含同名 Python 包 | `python -m` 优先加载调用目录，可能绕过原传输实现。改为 `-I -B -c` 隔离启动，显式插入父进程准确包根目录；凭据仍只经 stdin 传递 | 真实子进程与回环 HTTP：同名包未执行，准确响应且只有一次 POST；源码与安装分别运行 |
| R1 调用收到 R2 观察 | 原入口及持久校验接受跨版本观察，可能混淆长度和最终用量语义。入口要求请求/观察同版本，持久读取执行相同核对 | 原非法调用拒绝且预算/状态不变；修正后原请求可结算；重算摘要的非法历史仍被拒绝且原库字节不变 |
| 读取原文后、导出意图前撤权 | 原实现已经向外部端口发送内容，最后才拒绝。现每次在意图事务内再次检查应用历史读权，与应用撤权排序 | 意图前撤权时端口读写均为零；恢复权限后原请求接续 |
| 外部读取返回时目标身份已变 | 原实现可能先写变化后的目标，最后才报 STALE。现在从入口冻结目标，并在每次后续 I/O 前检查刚完成操作后的身份 | 读取发现换绑时零写入；写后换绑停止后续读取，恢复原目标后按原 key 对账且不重复写入 |
| 未验证 Generation 值触发深拷贝 | `asdict` 在校验前执行调用者对象的 `__deepcopy__`。改为逐字段构建并验证 Request | 八个输入字段分别拒绝不透明对象为 INVALID_INPUT，不调用其复制方法 |

初始六项回归在旧源码和旧安装各失败六项，覆盖以上五类问题；这些失败是缺陷复现，不计入通过数。最终新增八个测试方法，包含意图后撤权和写后换绑的接续检查；字段轴为方法内子例，不另计套件数量。证据日志中的本地项目路径已替换成占位符。

## 顺序和适用范围

导出授权以本次意图事务为准：先撤权则不进入端口 I/O；意图获准之后的撤权不能承诺撤回已发出的字节。最终确认仍检查权限；被拒绝则保留原内容身份和未确认意图，恢复获准后先按原 key 查询，不能重复生成或换存储绕过。端口仍是可信适配器，须保证身份稳定；这些检查不能原子约束外部系统或防御虚报身份的恶意代码。

存储和合法值的布局未变，没有迁移或重建原库；新校验只拒绝不满足版本合同的混合历史。原未知发送/未结预算保持，未引入自动重试、并发发送、远端取消或新的清账入口。真实服务、消费者 R3 接入、完整故障矩阵仍待验。本轮合成结果不代表生产资格。
