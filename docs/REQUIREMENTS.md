## 用户与交付结果

应用或 Agent 通过一个 Python 公共入口使用本地、商业大语言模型。已支持且已验证的目标可通过配置选择；业务不处理厂商 URL、凭据、SDK 或响应字段。模型的质量、容量、价格和能力差异仍须可见。

首个交付形态是可独立安装的嵌入式库。无须安装某个业务应用、启动中央网关或接入指定存储服务，便能在合成服务上完成登记、执行、读回与恢复示例。真实模型另按准确服务、模型、模式和权限验收。

## 功能要求

| ID | 要求 | 验收条件 |
| --- | --- | --- |
| MR-01 | 配置切换 | 同一业务请求结构从本地切到商业再切回；新调用绑定新修订，旧调用和原回执保持；非法配置不得部分生效 |
| MR-02 | 按需路由 | 按任务类别和必需能力选择已配置目标；无合格目标明确拒绝；不静默降级或扩大外发范围 |
| MR-03 | 多模型并行 | 支持不同任务并行，以及显式一次计划内多个独立子调用；每个子调用都有原身份、目标、状态、预算和结果；部分失败不抹掉成功分支 |
| MR-04 | 协议适配 | 首批文本、非流式 Responses 与兼容 Chat Completions；分别验证编码、响应完整性、终结、输出合同和 usage；协议名不代表全部能力已支持 |
| MR-05 | 持久与幂等 | 原身份相同且完整输入一致返回原登记回执；改变输入冲突；发放、捕获、保存、结算各中断窗口不产生盲目重发 |
| MR-06 | 预算与资源 | 同一协调范围内，全局、预算池与共享资源组的适用限额共同生效；精确累计，配置须核持久绑定，不因改别名、重分组、切模型、重启或降额清零 |
| MR-07 | 取消与恢复 | 取消先于发放则不发送；父计划取消先持久阻止全部子项新发放，再分批处理；发放在先保留在途事实，UNKNOWN 不因本地超时、租约过期或进程退出自动退款/释放 |
| MR-08 | 当前许可 | 登记、发放与交付各核对适用权限；应用准入版本失效阻止尚未发放的旧请求；父计划取消同样阻止子项当前交付，迟到结果不恢复业务采用权 |
| MR-09 | 结果可核对 | 准确输入/发送体/响应、配置与协议版本、提供方报告身份及用量可关联；观察缺失保留未知，不补造实际模型、账户或费用 |
| MR-10 | 有界与秘密隔离 | 请求、响应、队列、历史、控制、等待均有上限；配置仅存凭据引用，值不进入公共结果、日志或持久快照 |
| MR-11 | 独立复用 | 独立安装后的最小消费者仅依赖公开接口；无私有业务模块/表依赖；应用接入仍保持其原子性与历史语义 |
| MR-12 | 迁移与退出 | 按版本声明迁移/拒绝条件；原请求、未决占用和历史可核对；不能恢复旧账、启动双写或伪造空库来完成迁移 |
| MR-13 | 可选监督接入 | 默认关闭且无评审模块也可独立运行；支持获准评审调用与中立证据交接；应用按版本化策略选择抽检、建议或关键步骤关口，具体范围见[可选监督](OPTIONAL_SUPERVISION.md) |

“应用无感”限定为已经支持、满足相同必需合同的目标之间切换，不承诺答案相同、任意协议即插即用或供应商恰好执行一次。新增协议需要实现适配器和通过相应验证。

## 配置与并发的用户语义

支持三种候选策略：默认目标、按任务类别选择一个目标、显式有界多目标计划。配置提供策略，调用方声明必需能力与允许的处理范围；两者取交集，配置不能扩大授权。首期不做自动质量评分选模型、竞速取首个结果或隐式失败回退。

已登记计划冻结子调用列表及配置。重复登记不重新路由；计划内配置变更不混入一半旧、一半新目标。新计划使用新配置。各子调用分别争取预算和槽位，可能排队、拒绝或失败；登记计划成功不承诺所有分支都能发放。应用决定等待、比较、采用或取消，Runtime 不合成业务结论。

同一资源可被多个 profile 指向，例如两个别名共用同一推理服务或账户配额。必须显式映射稳定资源组，不能通过新别名绕开共享上限。同一物理资源被两个独立数据库管理时，本库不能保证合计并发；部署方须合并协调范围或另提供经验证的外部协调机制。

## 首期限制

- 先限定单机、本地受支持文件系统、一个持久协调库及其合作进程；不共享写入 NAS SQLite，不声明分布式全局限流。
- 首期只执行有界文本生成；工具执行、多模态、流式、模型训练/权重管理不在本轮范围。
- 凭据批准、服务处理许可与能力证据分别绑定；本地地址或名为 local 的 profile 不证明不外发。
- 生成额度、控制预留、内容容量、实际磁盘可用性分别判断；查询/取消/原对账不借新生成预算，但仍有权限与容量边界。
- token/字节/调用次数预算不等于货币硬封顶。金额预算需要准确价格版本、计费维度和账单对账后另行实现；没有价格时不得显示为零费用。
- 业务材料、纠错、引用真实性、知识准入、生产控制和最终采用留在调用方。Runtime 不接管这些决定。
