# R3 已结束历史的预算接续候选

2026-11-27；基于已合并 PR #7 `5c73203`。新增公共值 `ClosedHistory`、`HostedModelRuntime.attach(..., closed_history=...)` 及同参数重开。版本仍为 `0.1.0a2` candidate，准确来源按本轮提交与 wheel 摘要绑定。原 R1/R2 和不带旧历史的 R3 打开方式保持。

## 职责与支持范围

宿主先验证、保留并封存原历史，证明旧调用与用量已经确定，然后提交只读的累计基线。Runtime 将基线与新调用逐项相加，使用同一预算检查；不再实现第二套消费侧额度判断。宿主仍负责原记录与字节校验、旧引擎停写及业务历史读取。组件不判断一个外部账本是否完整，也不把源摘要当成外部签名。

| 字段 | 含义 | 新调用如何使用 |
| --- | --- | --- |
| `source_sha256` | 宿主核验的封存来源摘要，64 位小写十六进制 | 与宿主、内容端口绑定共同写入原 `rt_host`；重开须准确匹配 |
| `issued_calls` / `input_bytes` / `output_used` | 已确认的旧累计发放次数、计费输入字节、输出单位 | `budget()` 返回旧累计加新账；发送前全部计入上限 |
| `request_count` | 旧请求历史占用，0–256 | 新登记按旧占用加新请求检查 `max_requests` |
| `control_slots` | 旧控制历史及不可回收预留，0–128 | 新控制按旧占用加新控制检查；满额仍允许原新控制幂等重放 |
| `payload_reserved` | 旧历史仍占用的载荷容量预留，0–128 MiB，默认 0 | 新登记计入 `max_payload_bytes`，结束不自动释放历史容量 |

这是**已结束历史**接续接口，没有导入在途请求、UNKNOWN、未结用量或执行令牌的参数。宿主不得将这些状态塞进已用值后声称迁移完成；存在这些状态时继续旧实现的原身份对账或拒绝切换。调用结束、用量确定也不代表关联控制操作已经完成：若对账意图已持久化而控制回执仍待完成，宿主必须先按原控制身份完成，再重新检查来源；不能只将其占用计入 `control_slots` 就冻结记录。恢复已封存历史时同样须核验这一条件。组件只接收累计基线，无法从计数判断外部控制记录是否闭合，检查职责仍在宿主。当前所有源计数均保持不可变，没有负数冲销、修改基线、清账或补发旧请求的入口。源模型批准不随基线授予，新服务仍须显式 `approve`。

`ClosedHistory` 的数值必须为严格整数；已发放数不大于旧请求数；无发放时输入与输出累计只能为零。来源完整性与逐项语义由宿主证明。源码审计不防止 Owner 恶意重写整套数据库与宿主输入。

## 打开、配置与中断

- 只在首次 `attach` 提交基线，随初始化同库提交。重开传回同一 `ClosedHistory`；遗漏来源或修改累计值会拒绝，不默认为零。
- 基线绑定没有改变原 `r3.hosted-store.v1` 的普通工作区；已有无基线工作区仍按原调用方式打开。带基线的工作区必须使用理解新绑定的候选版本。
- 合法 profile 切换、取消、恢复或同请求重放均保留基线。存在旧或新请求时，从接入完成起即固定初始预算池/资源组，不等待第一条新请求；真正零请求历史继续允许原有配置调整。不可通过改名清账；低于当前累计的限额可保留配置，但新增发放仍按实际累计被拒。
- 原历史已有容量超过新候选支持范围时，拒绝接续；这个接口不提供扩容、归档或免费回收。宿主应在封存前检查新请求和控制的剩余空间。
- 附带公开的 `ModelRuntime.validate_configuration(bytes)`（Hosted 继承）只返回规范配置 bytes，供宿主在封存之前拒绝非法配置；不访问凭据、不批准目标、不执行模型。
- `attach` 原有提交未知语义保持。响应丢失时先按原绑定重开核对，不再提交新的历史来源。
