## 强制终止与独立恢复

Responses、Chat Completions 各覆盖下列七个窗口，共 14 个子例，计在一个新增测试方法中。测试连接实际本机 HTTP 服务，在检查点执行真正的 `SIGKILL`；必须看到准确检查点标记、加载来源及 `-SIGKILL` 退出码，提前导入失败不能算通过。随后分别启动全新检查进程与全新恢复进程。

| 强制终止位置 | 已持久发放 / 实际 POST / 已捕获 / 已结算 | 新进程应有结果 |
| --- | --- | --- |
| 发放事务提交前 | 否 / 否 / 否 / 否 | SQLite 回滚本次发放与应用计数；原登记可接续首次发送 |
| 发放提交后、发送前 | 是 / 否 / 否 / 否 | UNKNOWN；保留输出预留与执行槽，不重新发送 |
| 远端返回后、捕获前 | 是 / 是 / 否 / 否 | UNKNOWN；不能由服务端已返回推断本地已捕获 |
| 捕获事务提交前 | 是 / 是 / 否 / 否 | 回滚未提交捕获；保留原 UNKNOWN 和预算 |
| 捕获提交后 | 是 / 是 / 是 / 否 | 准确读回原字节，本地结算一次 |
| 结算事务提交前 | 是 / 是 / 是 / 否 | 应用结算计数与 Runtime 用量一起回滚；重开后共同结算 |
| 结算提交后、返回前 | 是 / 是 / 是 / 是 | 原回执、用量和应用计数保持，重复接续不再次结算 |

每个子例核对准确输入/wire/响应、登记回执、实际 POST 路径与次数、应用登记/发放/结算计数、SQLite `integrity_check` 及预算。恢复进程明确禁止调用传输；首次恢复后再重放两轮，比较完整 SQL 记录及公开状态。没有捕获的窗口在恢复前后完整记录相同。发放提交前被杀的原请求另验证可以首次发送一次。

这些是同步检查点上的实际进程终止，不等于设备断电、磁盘丢写、杀死仍在传输的子进程或所有时间窗口。原来已发放而未捕获的请求仍可能长期占用额度，不能为了继续任务擅自重发或清账。
