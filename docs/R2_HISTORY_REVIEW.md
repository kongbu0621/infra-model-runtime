## 问题与修复

| 问题 | 修复与反向检查 |
| --- | --- |
| 配置控制的 sequence 连续，但配置修订可以倒序；批准也可能落在其准确目标尚不存在的位置 | 按持久管理顺序重建配置修订，要求 expected 是准确整数并指向当时修订；批准必须匹配当时配置中的准确目标。拒绝交换配置顺序、把旧批准移到目标更换之后以及非法 expected |
| 应用命令只检查摘要，未复核公开值约束 | 持久读取同样要求有界 UTF-8 字符串；拒绝 null、布尔、数字、集合及超限字符串；合法空命令保持 |
| 发放截止只比较数值，等值浮点数被当作整数 | 同时验证准确整数类型和原截止计算关系；旧 UNKNOWN 的预算/占用不得因校验或恢复而释放 |
| 模型表或所需列缺失被报成普通 STORAGE_ERROR | 与核心布局处理一致，将相应 SQLITE_ERROR 归为 INTEGRITY_FAILURE；真实 I/O 和 BUSY 保持原分类，不自动修复原库 |

合法 A→B→A、相同配置的新修订、停用时预先批准、撤销未配置目标、旧控制重放与空应用命令保持；旧批准重放不会替换当前批准。新审计验证记录间的一致性，**不构成针对能够整体重写数据库与校验值的恶意宿主的认证机制**。
