## 复用和新实现的界线

既有实现可作为配置、协议、幂等、预算和故障检查的抽取来源，但逐文件核对权属、依赖、私有内容和准确版本。这里只公开可独立理解的通用合同与合成夹具；私有来源清单留在源仓。不得把私有仓历史、真实数据、部署路径或凭据复制到公共 Git 历史。

路由计划、多资源组并发、执行槽与未结算用量分离、独立载荷后端、公共事务端口、迁移工具都是需单独实现/验证的增量。移动文件、改变包名或编译通过不能证明这些能力已经具备。

公开仓、可安装包、软件发行、独立采用、真实服务验收和部署是不同结果。当前没有独立使用证据，不把一个合成示例或两个协议适配器算成两个真实消费者。发行前落实许可证与依赖兼容性；不凭 public 可见性推断已获得全部第三方再许可条件。

## 可选监督增量

[MR-13 / 可选监督](OPTIONAL_SUPERVISION.md)是长期可选能力，不成为 R1–R5 基础包交付的统一前置。当前固定职责、模式、动态切换、信任范围、观察事件及同链时间/额度限制，SV-01–18 全部运行检查为 NOT_RUN，包含评审取证不循环依赖目标关口、关闭后的旧调用接续及抽检资源竞争。

R1 保留中立观察与事务准入接缝，off 不引入评审依赖。R3 后由首个消费应用先实现有限的结果抽检/建议，结合独立参考比较有/无监督的检出、误报/漏报、质量与总成本。然后按有明确标准的关键步骤实现执行前/采用前 gate，验证当前版本绑定、并发失效、故障待检查与共享资源无循环等待，再扩展多步骤过程观察。

未实现或未满足的 gate 必须明确拒绝，不能以“先做 advisory”为由运行原本要求 gate 的关键任务。模型信任提升与减少监督须有任务范围证据及应用策略决定；模型自评、考分或一次成功不替代验收。新的模型调用与真实采用证据分别留存，不把外部研究或现有串行测试算作监督已通过。

## 开发环境与接续

每台机器先核对本项目已有虚拟环境与工具目录，再使用它们验证。运行来源与源码来源分别记录；不将新组件安装进其他项目环境或全局目录。隔离安装验收、正式依赖升级和服务部署分别实施，保留现有业务安装。

Python 依赖使用本机本项目的专属虚拟环境，不跨机器复制环境或为每轮日常复核另建日期目录。Mermaid 渲染器等文档工具按各自生态放入项目专属工具目录；若采用基于 Node 的 CLI，其 npm 依赖和浏览器缓存单独管理，不能以激活 Python venv 代替隔离。先查已有工具，确有缺口才安装，记录版本/锁定依赖与实际调用来源；默认不做系统全局安装。运行时包不依赖文档渲染工具。只改文字且图示源码/展示条件未变时，复用适用的既有渲染证据，不宣称重新渲染过。

本轮通过 PR 提交设计，不执行 NAS 接入、主干同步、业务安装或模型付费调用。后续沿已有授权推进可完成的源码和合成验证；真实服务阶段先核对已有 endpoint、凭据引用、数据处理许可及数值预算，缺失项保持待验，不要求将秘密贴入聊天。
