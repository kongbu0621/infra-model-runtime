## 导出恢复矩阵

新增三个测试方法，覆盖 input、wire、response 三种载荷，共 48 个内部子例；它们已经包含在完整套件的 138 项中，不另行累计为测试方法。新专项使用合成 Responses 调用和内存内容适配器；两协议 HTTP 等既有检查继续随完整套件执行。

| 检查 | 子例数 | 核对结果 |
| --- | --- | --- |
| 导出意图与确认事务，各自提交前、COMMIT 未执行、COMMIT 已执行但确认丢失、提交后错误 | 3 种载荷 × 2 个事务 × 4 个窗口 = 24 | 错误分类、提交状态和原操作身份准确；未确认提交的意图不会开始外部 I/O；确认事务失败不删除外部已有副本 |
| 外部写入前 / 写入后发生 OSError 或 KeyboardInterrupt | 3 × 2 × 2 = 12 | 已写入的按原 key 读回，不重复写；未写入的在重新确认不存在后才尝试写入 |
| 外部首次读取 / 写后读回发生 OSError 或 KeyboardInterrupt | 3 × 2 × 2 = 12 | 未知读取不当作不存在；未成功读回不标为已确认；原意图保留并按原 key 接续 |

每次失败后重开 Runtime，用相同请求、角色和目标重复接续两轮，核对完整内容 key、准确 bytes、调用登记回执、全部非导出记录、调用预算、端口读写尝试及实际新增副本次数。首次写入明确未完成时允许再次调用 `put_if_absent`；已完成时只读回。各子例最终只产生一份原身份副本。恢复过程显式禁止模型传输，原已完成调用不重发。

SQLite 提交结果丢失仍报告 `unknown`，不能因测试控制器知道是否执行过 COMMIT 而替产品猜测成功。检查过程直接读取合成库，仅用于验收实际持久结果；正常消费者继续使用公开入口按原身份接续。

本轮是受控普通异常与 Python 中断注入，未对内容端口执行实际进程强杀、设备断电或真实远端对象存储故障。内存适配器不等于 Ledger 接入。已有[实际 SIGKILL 检查](R2_PROCESS_REVIEW.md)覆盖其声明的调用发放/捕获/结算窗口，两者范围分开记录。
