## 已复现的问题

原实现核对 JSON 字节摘要，但只检查少数字段类型，没有充分核对当前状态、观察、取消和回执之间的关系。受控错误写入若也重算了摘要，可能产生以下结果：

| 不一致记录 | 修复前表现 | 本轮处理 |
| --- | --- | --- |
| 仍有发放凭据却把 issued 改为 false，或仍有取消回执却把 cancelled 改为 false | 可能再次返回发放令牌，或发放已取消调用 | 严格检查字段集合、发放凭据存在条件及取消事实；打开/写入前拒绝不一致 |
| 负预留、用量/终结/结果投影不符，或清空历史却保留已观察状态 | 预算可能包含负数，仍交付结果或漏检历史缺失 | 从已保存的有界观察顺序独立推导当前结果、用量、预留、隔离与观察修订，再精确比较 |
| 登记、观察、取消或管理回执身份/版本/摘要错误 | 可能返回不属于原请求的回执；未访问的控制行缺少审计 | 核对回执完整字段与原身份/意图，管理回执在每次操作前与写入提交前一并审计 |
| 配置修订与管理历史不符，或调用来自尚不存在的配置修订 | 只核整数类型会漏检关系错误 | 配置修订对应连续的配置控制回执，调用冻结修订不得大于当前修订 |

独立校验位于 [storage.py](../src/infra_model_runtime/storage.py)，不依赖业务投影或应用存在。非法形状、类型、版本、序列和可证明的不一致统一报 INTEGRITY_FAILURE；不补默认值、不改写损坏原件。JSON 比较区分整数、浮点和布尔值。配置更新在同一事务内写回控制记录和元数据后再审计，不把尚未完成的事务中间状态当成持久坏库。

这是内部一致性检查，不是认证历史的安全边界。摘要不能抵御同步重写全部记录的恶意修改或完整旧快照回滚。观察修订允许合法跳号，因此不能据此断言未保存的中间修订必曾存在；本轮检出的是保留记录内部的可验证矛盾，不宣称证明任意历史从未丢失。

- 核对损坏拒绝后的完整逐表原状；测试恢复准确原记录后，原登记/观察/取消/配置回执保持，已取消仍拒绝发放，已发放仍拒绝再次取得令牌。
