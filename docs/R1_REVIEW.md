## 已修复问题

| 问题 | 旧版实际结果 | 修复与验收 |
| --- | --- | --- |
| SQL 自动回滚后继续使用端口 | `INSERT OR ROLLBACK` 冲突被捕获，后续 UPDATE 在 autocommit 下生效；外层却报 not_committed | 错误使端口持续失效；每条 SQL 与 hook 返回均检查事务仍在。后续 SQL 不执行，完整库保持，修正后同控制 ID 可以接续 |
| 最后一次 audit 吞掉重入错误 | 提交前审计捕获嵌套 Runtime 错误后仍能提交 | 每个 hook 出口及最终提交前核对重入标志；原登记和应用写入全部回滚，恢复原审计后同输入成功 |
| 控制回执单侧缺失 | 应用命令重复执行；配置控制重试误报普通冲突 | 新增持久 control_count，与回执共同提交；打开、操作前和提交前核对完整行数。拒绝缺失后重执行，不自动补回执；精确恢复原测试行后原回执重放不增量 |

普通 SQL 错误同样禁止在该端口继续查询或写入；不要求等到回调返回才失败。新增计数写失败另验应用变更、回执及元数据一起回滚。计数和摘要用于发现所测不一致，不是恶意直接改库、同时伪造多项记录或旧库整体回滚的防护承诺。

## 合同变化

`CallState` 为 `r1.state.v2`，增加 `result_sha256`：成功结果准确 UTF-8 字节的 SHA-256；无正文时为 None。状态不返回结果正文，不据此认定内容真实或业务合格。应用可在事务内用它核对自身结果投影，业务标准仍归应用。用量补报和取消不改变原结果摘要。

存储为 `r1.store.v2`，增加 control_count；其余请求、配置、观察及回执的版本保持 v1。显式拒绝旧 v1 合成库，既不静默迁移也不创建替代空库。本轮未发行或安装，旧原型库与历史证据保留；今后真实业务迁移仍属 R3。
